# Governance

FractawOS is an open-source project maintained through public development and reviewed contributions.

The project aims to remain open to community participation while protecting architectural stability, security, and long-term maintainability.

## Project ownership

The FractawOS GitHub organization contains the official repositories maintained by the project.

Organization membership is not required to contribute.

Anyone may fork public repositories, open issues, submit pull requests, participate in discussions, and build compatible modules.

Write access to official repositories is granted based on project responsibility and maintenance needs.

## Roles

### Contributors

Anyone who contributes code, documentation, testing, design, bug reports, proposals, or modules.

### Maintainers

Contributors trusted with regular review and maintenance responsibilities for one or more repositories.

### Core maintainers

Maintainers responsible for platform architecture, public SDK contracts, security-sensitive decisions, and cross-repository coordination.

### Organization owners

Maintainers responsible for organization-level administration and access control.

## Decision process

Minor implementation decisions may be handled through normal pull request review.

Changes that affect public APIs, module contracts, security boundaries, architecture, compatibility, or project governance should be discussed publicly before implementation.

The project should prefer technical reasoning, reproducible evidence, maintainability, compatibility, and user control.

## Official modules

Official modules are maintained within the FractawOS organization.

A community module may become Official when it demonstrates:

- clear usefulness;
- architectural compatibility;
- stable maintenance;
- adequate documentation;
- sufficient testing;
- appropriate permission usage;
- long-term relevance to the project.

Becoming Official is a project governance decision, not an automatic consequence of popularity.

## Independence

Community developers retain ownership of their own external modules unless they explicitly transfer them.

A module may remain community-maintained indefinitely.
